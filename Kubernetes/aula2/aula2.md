## apply

kubectl apply -f [file name]

if not exists k8 creates if it exists k8 will update


## 
each configuration file have 3 parts:

metadata - name, ...
specification - basically put every kind of configuration, the atributes are specify for every kind of component you are creating
status - automatically generated by k8, the kubernentes always will compare the desired status with a actual status, if not match so k8 will try to fix it, k8 self healing .


etcd holds the current status of any k8s component

## demo: complete application setup with kubernetes componentes

web app --> mongo express/ external service --> mongo express pod --> mongo db internal service --> mongo DB

mongodb: no external requests, only same components of the cluster can talk with db.
mongo express: connect to db, authenticate to db, env variables
    reference with: 
        config map: with db url
        secret: db user, db password


external service to be have access by browser, need ip and port of external service


## creating secret

criamos um secret para o username e password do root, foi usado base 64 encriptaçao.
como no print abaixo

apos isso fazemos o apply 
k apply -f secret.yaml
k get secret

nota importante: é necessario primeiro criar os secrets e depois o deployment, senao o deployment nao consegue identificar a password e o username


## external service
type: load balancer
assings service an external ip address and so accepts external requests
node port: must be between (30000 - 32767)

port for external ip address
port you need to put into browser
